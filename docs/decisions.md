# Decision log

| # | Decision | Why | Alternatives rejected |
|---|---|---|---|
| 1 | Node array order = work order (single yarn in v0.1) | A graph is then crochetable by construction; counter and export are trivial. Matches the "current loop" insight in Guo et al. 2020 and knittable stitch meshes. | Unordered graph + topological sort (must then prove an order exists) |
| 2 | Chain spaces and rings are entities with ids; anchors point at node *or* space | Lace-first requirement; a stitch "in ch-3 sp" has no single chain it belongs to | Anchor to the middle chain (loses meaning, breaks charts and notation round-trip) |
| 3 | Decreases and clusters are one node with several anchors; increases/shells are several nodes with one anchor | Uniform: degree carries the meaning; no special node types | `inc`/`dec` node types |
| 4 | Graph always stores US stitch types; UK is a parse/print dialect | One vocabulary downstream | Storing source names |
| 5 | Hand-written lexer + recursive-descent parser in TypeScript | Positioned, crocheter-language diagnostics; error recovery per round; zero dependencies | PEG/parser generator |
| 6 | Only one notation parser (TS). Lab reads compiled graph JSON | Two parsers would drift; the graph is the contract | Python port of the parser |
| 7 | Stitch-level mass-spring network specified in `spec/physics.md`, solved twice | Shape (cup/flat/ruffle) is a metric question; yarn-level contact (Kaldor et al.) is far beyond need. Second-neighbour "bend" springs give the bending term the lit review asks for without a triangulation of lace | Yarn-level sim; FEM shells on a triangulated graph (lace has holes) |
| 8 | Round-by-round growth as the solve strategy, deterministic perturbation instead of random noise | Mirrors making; gives every intermediate round; reproducible across languages | Global solve from a flat start (crumpled minima on closed shapes) |
| 9 | Analytic flatness uses absolute circumference vs 2πρ with a compliance band for chain spaces | Matches Gauss–Bonnet and crocheters' "+6 per round" rule; chains are slack-tolerant, which is why lace is forgiving | Per-round increase rule only (misses accumulated error) |
| 10 | Vite + React + TypeScript, hash routing, `base: './'`, PWA | Static, works on GitHub Pages at any path and offline on a phone | Next.js (needs a server model we do not have) |
| 11 | `stitch_params.json` lives in `spec/` | It is a contract file both sides load; lab's fitting overwrites it | Under `lab/` (app would reach into lab) |
| 12 | Python env via `uv`, reports are jupytext notebooks executed to HTML and committed | One command, reproducible, viewable without running | Committed `.ipynb` (noisy diffs) |
| 13 | Spring rest lengths come from the fabric's intrinsic ("prescribed metric") geometry, not rectangular cells (`lab/SPEC_NOTES.md` N1–N4) | With rectangular-cell shear/bend rest lengths, flat circles cupped and lace ruffled in the sim: the reference state must itself be realisable flat when the stitch counts say flat | Literal physics.md v0.1 network (kept in the lab as `variant="spec"` for comparison) |
| 14 | `tau_flat` = 0.25 | The network has little resistance to isometric bending, so small metric mismatch shows as waviness ~√e; flat fixtures reach 0.18, nearest non-flat is 0.60 | 0.10 (misclassifies the flat dc circle) |
| 15 | The cursor of a joined round starts at the join stitch; the first `next st` is that stitch | Simple, uniform rule; generators and corpus rely on it | "Travelling" slip stitches skip the join stitch (closer to how crocheters read it; revisit in notation v0.2) |
| 16 | Vintage corpus not gathered; 16 original CC0 patterns instead | The session's network policy blocks gutenberg.org / archive.org and patterns must not be reconstructed from memory | Transcribing from memory (unverifiable provenance) |
| 17 | Interactive solver is the same L-BFGS as the lab, not XPBD (lit review synthesis recommends XPBD) | Agreement with the reference sim is the contract; an identical minimiser on an identical network makes drift testable. XPBD is the plan once real-time interaction (dragging, pins) matters — roadmap Phase 3 | XPBD now (different fixed points, harder to pin to the lab) |
| 18 | No discrete-shell bending energy in Phase 1 (lit review recommends one) | Lace has holes, so there is no triangulation to hang hinges on; second-neighbour springs with metric rest lengths were enough to classify the fixtures. The cost is real: weak bending resistance makes the sim over-sensitive (see `docs/review.md` R1–R2, `docs/sim_corpus_report.md`). Roadmap Phase 3 | Hinge bending on solid regions only (two models to keep consistent) |
| 19 | Flatness check is the concentric-round rule, not per-vertex angle deficit (lit review recommends the general form) | It is the rule crocheters already use and it yields "N stitches over" messages; the lab computes angle deficit for reports. General per-stitch curvature in the app is roadmap Phase 3 | Angle deficit in the app now (needs a triangulation of lace) |
| 20 | No CrochetPARADE import/export in Phase 1 | Out of scope for a first build; listed in roadmap Phase 5 (interoperability) | — |
| 21 | **Open: no licence chosen for the code.** The corpus is CC0; the code has no LICENSE file | Choosing a licence is the owner's decision, not the build's | Picking MIT/Apache/GPL unasked |
